# 日常操作手册

## 记录任务

### 通过 Obsidian CLI（Obsidian 运行中）

```
obsidian append file="00_To-Do" content="- [ ] 新任务描述 📅 2026-04-05"
```

任务自动追加到 `00_To-Do.md` 末尾，落入 `## Inbox` 区域。

### 通过直接写文件（Obsidian 未运行）

打开 `10_Inbox/<成员名>/00_To-Do.md`，在文件末尾追加：

```markdown
- [ ] 新任务描述 #next 📅 2026-04-05
```

### 关于成员名

如果不知道成员名，查看 `10_Inbox/` 下有哪些子目录（排除 `Agents/`）。通常就是用户的名字。

## 记录想法

### 通过 Obsidian CLI

```
obsidian daily:append content="刚想到一个点子..."
```

### 通过直接写文件

打开当天日记 `10_Inbox/<成员名>/YYYY-MM-DD.md`，在 `## Thoughts` 下追加内容。

如果今天的日记不存在，从模板创建：

```
obsidian daily:open
```

或者手动复制 `99_System/Templates/tpl_daily_note.md`，将 `{{date:YYYY-MM-DD dddd}}` 替换为今天的日期。

## 全自动整理算法

整理就是把 Inbox 里的乱七八糟变得有条有理。以下是完整步骤：

### Step 1: 读取所有 To-Do 文件

```
找到所有 10_Inbox/*/00_To-Do.md 文件
逐个读取文件内容
```

### Step 2: 解析文件结构

To-Do 文件的结构：

```
# To-Do
## Readings        ← 阅读清单（固定在顶部）
## 项目A           ← 项目 Heading（中间区域）
## 项目B           ← 项目 Heading（中间区域）
## Inbox           ← 收集箱（固定在底部）
```

识别每个 Heading 及其下的任务列表。

### Step 3: 分类 Inbox 中的任务

对 `## Inbox` 下的每个任务：

1. **读取任务内容**：理解任务描述
2. **匹配已有 Heading**：
   - 如果任务明显属于某个已有项目 → 将任务文本从 Inbox 区剪切，粘贴到该项目 Heading 下
   - 如果是阅读/观看类内容 → 移到 `## Readings`，加 `#read` / `#watch` / `#listen`
3. **创建新 Heading**：
   - 如果任务属于一个尚未有 Heading 的新项目 → 在 Readings 和 Inbox 之间插入新 `## 项目名`
   - 新 Heading 下第一行加 `> [[30_Projects/项目名]]`
   - 将任务移到新 Heading 下
4. **无法判断** → 留在 Inbox，不强行分类

### Step 4: 补全标签

对所有没有标签的任务（不仅是 Inbox 的）：

| 判断 | 加标签 |
|------|--------|
| 紧急、可以马上做 | `#next` |
| 需要等别人回复/操作 | `#waiting` |
| 以后再说、不紧急 | `#someday` |
| 阅读材料 | `#read` |
| 不确定 | 不加，留着下次整理 |

### Step 5: 补全日期

对有时间要求但没有 `📅` 日期的任务，根据上下文建议截止日期。不确定的不加。

### Step 6: 归档已完成

扫描所有 `- [x]` 任务，将它们从当前位置剪切，追加到同目录的 `09_Done.md` 末尾。

归档格式保持原样，Tasks 插件已自动添加了 `✅ YYYY-MM-DD` 完成日期。

### Step 7: 生成整理报告

在当天日记的 `## Thoughts` 区追加整理摘要：

```markdown
### 整理报告 (HH:mm)

- 处理 Inbox 任务 X 个
- 移到「项目A」: 2 个任务
- 新建项目「项目B」
- 补全标签: 3 个 #next, 1 个 #waiting
- 归档已完成: 4 个任务
```

### 安全规则

- 整理前先展示计划给用户确认（watch 触发的轻量分拣除外）
- 不删除任何任务，只移动位置
- 不修改 `00_Dashboard/` 和 `01_Tasks.md`（这些是查询视图）
- 不修改已有任务的描述文本

## 智能日报生成

### Step 1: 收集任务

读取所有 `10_Inbox/*/00_To-Do.md` 中的未完成任务（`- [ ]`）。

### Step 2: 分类排序

按紧急/重要矩阵分为四类：

**🔴 紧急且重要**（今日必做）：
- 今天到期的任务（`📅` 日期 = 今天）
- 已过期的任务（`📅` 日期 < 今天）

**🟠 重要不紧急**（可以推进）：
- 标记 `#next` 的任务
- 明天到期的任务

**🟡 紧急不重要**（等待跟进）：
- 标记 `#waiting` 的任务

**⚪ 不紧急不重要**（暂不处理）：
- 标记 `#someday` 的任务
- 截止日期在未来 3 天以后的任务

### Step 3: 生成 Top 3

从 🔴 和 🟠 中选出最重要的 3 个任务作为 "今日 Top 3"。选择依据：
- 过期任务优先
- 今天到期的其次
- `#next` 再其次
- 有明确截止日期的优先于无日期的

### Step 4: 格式化输出

```markdown
## 今日行动计划 (YYYY-MM-DD)

### 🔴 今日必做 (Top 3)
1. **任务描述** — 原因（今天到期 / 已过期 N 天）
2. **任务描述** — 原因
3. **任务描述** — 原因

### 🟠 可以推进
- 任务描述（来自：项目A）
- 任务描述

### 🟡 等待跟进
- 任务描述（等 XXX 回复）

### 📊 统计
- 总待办: N 个
- 过期未完成: N 个
- 今日到期: N 个
```

### Step 5: 写入日记

将上述内容追加到当天日记的 `## Thoughts` 区。不修改 To-Do 原文件。

## Agent 记忆持久化

### 何时写入 Journal

| 事件 | 写入内容 |
|------|---------|
| 完成重要任务 | 做了什么、结果如何 |
| 做出关键决策 | 决策内容、原因、备选方案 |
| 对话结束前 | 本次交互的要点摘要 |
| 产出文档/代码/报告 | 摘要 + 存放路径 |
| 用户说"记住这个" | 用户指定的内容 |

### 写入方式

追加到 `10_Inbox/Agents/Journal.md` 末尾：

```markdown
### YYYY-MM-DD HH:mm — 标题

正文内容。

相关文件：[[30_Projects/项目名/文件名]]
```

### 产出内容放置

Agent 产出的文档、报告、分析等，按 PARA 规则放到对应目录：
- 项目交付物 → `30_Projects/<项目名>/`
- 知识整理 → `40_Resources/`
- 长期维护的内容 → `20_Areas/`

在 Journal 中记录产出的摘要和路径。
